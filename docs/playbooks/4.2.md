# 4.2: Minimum functionality

**Store:** Apple. **Resubmit without a new build:** only when the steps below say so.

## What it means

The reviewer found the app too thin, or felt it was a website in an app wrapper.

## Fix

1. Run `node tools/presubmit/index.mjs --platform ios --app apps/shopper --brand <brand file>` and confirm native_screens passes: every one of the nine screens is a native screen and no web view library is linked.
2. Check the business has a real catalog: at least a dozen live products with photos, a few categories and at least one reel. An empty store reads as a shell.
3. In the review notes, list what the app does that the website does not: reels, order tracking, saved addresses, push for order updates, rewards.
4. Resubmit the same build once the catalog and the notes are fixed. Change the build only if the gate found a web view.

## If it happens again

A second rejection under the same guideline (ignoring any bracket, so 4.3(a) and 4.3 count together) opens a review task in the
Platform Console and blocks the next resubmit. Do not send the app again: a person on our team reads both rejections, decides the
fix, and resolves the task with what was done. Only then can the app go back to review.

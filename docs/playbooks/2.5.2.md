# 2.5.2: Code downloaded after review

**Store:** Apple. **Resubmit without a new build:** only when the steps below say so.

## What it means

Apple thinks the app changes its behaviour or features after review, often after an over-the-air update was noticed.

## Fix

1. List the over-the-air releases on the app’s runtime in the Platform Console. Over-the-air updates may only fix JavaScript, styling, images and copy: never a new feature or a change of purpose.
2. If a release added a feature, roll it back and ship the change in a store build instead.
3. Reply in Resolution Center describing what the updates change, then resubmit.

## If it happens again

A second rejection under the same guideline (ignoring any bracket, so 4.3(a) and 4.3 count together) opens a review task in the
Platform Console and blocks the next resubmit. Do not send the app again: a person on our team reads both rejections, decides the
fix, and resolves the task with what was done. Only then can the app go back to review.
